# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Website for **AI Code Rating (ACR)**, a three-character disclosure of how AI was used in a code project (maintainer expertise `A`–`E`, AI share `0`–`4` (none, then quarters), oversight `a`–`e`, forced to `a` when AI share is `0`), published by projects in an `ACR.md` file. Built with [Eleventy](https://www.11ty.dev) v3 and Nunjucks. Styling is hand-written CSS (no CSS framework). Domain: aicoderating.com (`site_url` in `meta.js`).

## Hosting

Static site. `_website/` is gitignored. Deploys are done from a local machine: build, then copy `_website/` to the web server. Server and deploy details are kept privately, outside this repo. Anything the site loads from another host (images, scripts, analytics) must also be allowed by the server's Content-Security-Policy, or browsers will block it.

## Extra Head Tags (Analytics)

`src/_includes/local/head.njk` is gitignored and included in every page's `<head>` only if it exists (`ignore missing`). It holds deployment-specific tags such as the analytics snippet, so they stay out of the source and clones get a site without them. Anything in a page's `<head>` is public (every visitor downloads it), so never put secrets there. The footer's privacy line is `analytics_note` in `meta.js`; set it to an empty string if a deployment has no analytics.

The GitHub organization profile (`ai-code-rating/.github`, file `profile/README.md`, checked out locally at `~/dev/github/ai-code-rating-readme`) repeats copy from this site. Whenever a change here touches any of the following, tell the user the profile needs the same update, and offer to make it:

- The home page intro sentence (`lede` in `src/content/index.njk`) and the "doesn't judge whether using AI is good or bad" line.
- Position names (Maintainer Expertise, AI Share, Oversight), their symbol ranges (`A`–`E`, `0`–`4`, `a`–`e`) and the end-point level names (Expert, Non-programmer, None, 76–100%, Verified, Unchecked) in `src/_data/levels.json`.
- The example rating `A2b` and what it means (Expert, 26–50%, Reviewed), and the badge URL and colour (`badge_colour` in `meta.js`).
- The file name `ACR.md`, and the "Rate Your Project" steps (rating form, add the file, validator, GitHub Action, ask to be listed).
- Page URLs it links to: `/#rate`, `/#rated`, `/validate/`, `/examples/`, `/faq/`, `/spec/`, and the repo, new-issue form picker, add-my-project form, `CONTRIBUTING.md` and `CODE_OF_CONDUCT.md` URLs (`url_repo`, `url_issue_new`, `url_issue_rated`, `url_contributing`, `url_conduct` in `meta.js`), and the Action's repo (`url_action`).
- Licences (CC BY 4.0 spec, MIT code), and the list of repositories in the organization (currently `aicoderating.com` and `action`; add any new repos there).

## Commands

```bash
npm run build   # rm -Rf _website && npx @11ty/eleventy
npm run serve   # rm -Rf _website && npx @11ty/eleventy --serve (local dev server with live reload)
npm run debug   # rm -Rf _website && DEBUG=* npx @11ty/eleventy
```

No test suite or linter. `node scripts/test-validator.cjs` (after a build) runs the validator page against good and bad sample `ACR.md` files with a stub DOM and prints each result. `node scripts/sync-action.mjs [path]` copies the checks, levels and js-yaml into the GitHub Action repo (default `~/dev/github/ai-code-rating-action`). Eleventy must stay at 3.1.6 or later: 3.0.0 renders `_data/*.js` empty on Node 26.

## Architecture

- **Input** `src/`, **output** `_website/` (gitignored). Config is `eleventy.config.cjs` (CommonJS, while `package.json` is `"type": "module"`).
- **Single source of truth for the levels:** `src/_data/levels.json` holds the maintainer levels, AI share bands, oversight levels, examples, the calculator's default answers, `no_ai_oversight_name` (shown instead of "Verified" when AI Share is 0) and `inconsistent` (maintainer/oversight combinations the form and validator warn about; the spec renders them too). It drives the home page tables, the spec page tables, and the calculator (via `src/content/js/levels.js.njk`, which renders `window.ACR` to `/assets/js/levels.js`). Change the levels there, never in templates or JS.
- **Rated projects:** `src/_data/ratings.json` lists projects that publish a rating (`name`, `url`, `acr_url`, `rating`, `desc`), shown in the home page's Rated Projects section (`#rated`, between Reading a Rating and the rating form; it replaced the made-up examples, whose `examples` entries in `levels.json` are now unused but kept so the Action's synced data doesn't change). This site's entry has `"self": true` and no `rating`; it uses `own_rating` instead. Every card's rating links to the project's `ACR.md` on GitHub (this site's too, for consistency; the footer badge still links to `/ACR.md`), its name to the repo, and a last "Your Project" card (`.ex-you`, in the template, not the JSON) links to the rating form and the add-my-project issue form. Check each new entry's `ACR.md` with the validator before adding it. If the list outgrows the home page, move it to its own page.
- **Site settings:** `src/_data/meta.js` — title, domain/URLs (including the public repo, issues and contributing guide), `spec_version`, `file_name` (`ACR.md`), badge colour.
- **Pages:** `src/content/index.njk` (home + calculator; its Roadmap section marks the current stage with the `now` class, currently 3. Adoption), `pages/faq.md` (`/faq/`), `pages/examples.md` (`/examples/`, rating examples for common setups; every rating must follow the spec's rules and pass the validator; ratings are shown with the `{% acr "A2b" %}` shortcode from `eleventy.config.cjs`) and `pages/related-work.md` (`/related-work/`, comparison with other AI disclosure standards; keep it fair and accurate), both inheriting `pages/pages.json`, `validate.njk` (`/validate/`), `404.njk`, `htaccess.njk` (`/.htaccess`: Apache 404 page, `Cache-Control` headers (fonts 1 year, JS/images 1 day since their names aren't content-hashed, HTML `no-cache`) and serving `/ACR.md` as UTF-8 text), `robots.njk`, `sitemap.liquid`.
- **Versioned spec** (`src/content/spec/`): each version is its own file (`0.1.md` → `/spec/0.1/`, tagged `spec`, front matter `spec_version`). `index.njk` renders `/spec/` from whichever version matches `meta.spec_version`. `changelog.njk` (`/spec/changelog/`) is built from `src/_data/spec_versions.json`. Each version file starts with `{% set s = levels %}`; Nunjucks runs before Markdown so its tables loop over `s`.
- **Releasing a new spec version:** (1) copy `levels.json` to `src/_data/levels_v0_1.json` (old version's number) and change the old file's line to `{% set s = levels_v0_1 %}` so its tables freeze; (2) copy the old version file to the new number, update `spec_version`/`spec_status`/`date_updated`; (3) add the version to `spec_versions.json`; (4) bump `meta.spec_version`. Never edit a released version's file except for typos.
- **Layouts:** `src/_includes/layouts/base.njk` (head, meta/OG tags, inlined CSS, a skip link, header/footer partials around `<main id="main">`, per-page `scripts` front matter list) and `page.njk` (long-form pages, `.doc` styles).
- **CSS:** `src/_includes/css/site.css`, inlined into every page by `base.njk`. The header (`partials/header.njk`) is a spec-sheet "data plate": a mono strip (spec version, Changelog, Related Work, GitHub) above a bordered row of a brand cell and one cell per section link, each centred under a small mono field name (Scale, Rating, File, Tool, Standard, Help); the current page's cell is shaded (`aria-current`). Its outer border is `--frame`, softer in dark mode. Space between home page sections is `margin-top` on `section`, not padding, so menu jumps to `#levels`/`#rate`/`#file` land on the heading; keep it that way. Colours are tokens on `:root` with dark values under `prefers-color-scheme` and `[data-theme="dark"]`. Positions 1/2/3 have fixed colours `--p1`/`--p2`/`--p3` used everywhere. Links and focus rings use `--link`, separate from the position colours. Headings use headline (title) case. Punctuation (periods, commas, etc.) always goes outside links, never inside the link text. Write an ellipsis as three dots (`...`), never the single `…` character.
- **JS** (`src/assets/`, passthrough): `theme.js` (Dark/Light/System toggle in the footer, Dark is the default and `<html>` ships with `data-theme="dark"` so no-JS visitors get it too; a saved choice in localStorage key `acrTheme` wins; loaded in `<head>`), `header.js` (sets `--header-h` to the sticky header's height so anchor jumps and the sticky rating panel clear it; the header is sticky from 720px up), `calculator.js` (the rating form; its README badge snippet comes in Markdown, HTML or reStructuredText from `BADGE_FORMATS`, all linking to `ACR.md`, and the chosen format is kept in localStorage key `acrBadgeFormat`), `acr-check.js` (the `ACR.md` checks, no browser or Node code: sets `window.ACRCheck` in a browser, a CommonJS module in Node; messages are built through a `fmt` the caller passes, HTML on the page, Markdown in the Action) and `validator.js` (the validator page's UI on top of it), all reading `window.ACR` so allowed values follow `levels.json`. The validator parses YAML with js-yaml (`CORE_SCHEMA`, so `updated` stays a string and must round-trip as a real date; the future-date warning allows a day of time zone slack, and the validator page and rating form use the visitor's local date; the body check ignores HTML comments and warns on an empty "How AI Was Used" section, so the form's placeholder comment counts as empty), an npm dependency copied to `/assets/js/vendor/` by `eleventy.config.cjs`.
- **Fonts:** self-hosted woff2 (Latin + Latin Extended) in `src/assets/fonts/`, declared in `src/_includes/css/fonts.css` and inlined before `site.css`; the two main Latin files are preloaded in `base.njk`. No requests to Google Fonts. Licences in `src/assets/fonts/LICENSES.md` (OFL). `.eleventyignore` stops Markdown under `src/assets/` being built as pages.
- **Icons and link preview:** `src/assets/img/favicon.svg` (three-bar mark, with dark-mode colours), `src/favicon.ico` (16/32/48 PNG fallback, copied to the site root), `apple-touch-icon.png`, and `og-image.png` (1200×630). Redraw the preview image with `python3 scripts/make-og-image.py` (Pillow; caches TTFs in gitignored `scripts/.fonts/`) after changing the headline, example rating or colours. The GitHub repo's Social preview (Settings → General) is a separate upload of the same file, so tell the user to re-upload it after a redraw.
- **This project's own rating:** `ACR.md` in the repo root (currently `B4c`). It's copied to the site as `/ACR.md`, and `src/_data/own_rating.js` reads its front matter for the footer badge (`partials/acr-badge.njk`), so change the rating only in `ACR.md`. The footer badge and the rating form's preview both load the real shields.io image (`img.shields.io/badge/ACR-<rating>-<colour>`), the same badge every project uses, so the server's CSP must allow `https://img.shields.io` in `img-src`. Every rating's badge is 64×20, so both `<img>` tags carry `width="64" height="20"` to avoid layout shift. Keep its `updated` date current.
- **GitHub Action** (`ai-code-rating/action`, checked out at `~/dev/github/ai-code-rating-action`, linked as `url_action` in `meta.js`): a `node24` Action with no dependencies or build step. `index.cjs` reports results as annotations, a job summary and outputs (`rating`, `errors`, `warnings`); inputs `path` and `fail-on-warnings` (stale dates only warn by default). Its `lib/` is generated by `scripts/sync-action.mjs` (`acr-check.cjs`, `acr-data.json` in the `window.ACR` shape, `js-yaml.cjs`), so after changing `acr-check.js`, `levels.json`, `spec_versions.json` or `meta.spec_version`, re-sync, run its `node test/run.cjs`, and tag a release there. An empty file is an error in the Action (on the page it's a prompt to paste). The Action's one extra check, not in `acr-check.js` because it needs the repo, warns when the README's ACR badge shows a different rating from `ACR.md`. Badges always load from `img.shields.io`, never from aicoderating.com: there is deliberately no badge service.
- **Filters:** `isoDate` (UTC `YYYY-MM-DD`), used by the sitemap and spec page. Don't use Liquid's `date` filter for dates — it shifts them a day in local time.
